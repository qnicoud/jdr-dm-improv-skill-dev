# ADR 0002 — Exécuter Gradle sous JDK 21

- Statut : acceptée (2026-10-16)
- Décision de pilotage : D4
- Source : `docs/research/01-stack-technique.md` §2

## Contexte

Le JDK système est OpenJDK 27. Gradle ne le supporte qu'à partir de la 9.8.0, ce qui sort de la fenêtre KGP 2.4.21 (Gradle ≤ 9.7.0). AGP 9.4 et Robolectric n'annoncent pas JDK 27. Robolectric exige JDK 21 pour les tests SDK 36. Un JDK 21 complet est installé dans `/usr/lib/jvm/java-21-openjdk`.

## Options

1. JDK 27 (système) : il faudrait Gradle ≥ 9.8, donc hors fenêtre KGP.
2. **JDK 21** : supporté par toute la chaîne, exigé par Robolectric, et probable plancher de Gradle 10.
3. JDK 17 : minimum AGP, mais insuffisant pour Robolectric avec SDK 36.

## Décision

- On exécute le démon Gradle sous **JDK 21** grâce aux critères de JVM du démon : `./gradlew updateDaemonJvm --jvm-version=21` génère `gradle/gradle-daemon-jvm.properties`, qui est versionné. Ces critères priment sur `JAVA_HOME`.
- On ne met **pas d'`org.gradle.java.home`** dans le dépôt (le chemin dépend de la machine).
- On ne met pas de plugin foojay en v1 : le JDK est déjà installé en local, et la CI le fournit avec `actions/setup-java` (Temurin 21).
- Le bytecode Android cible **Java 17** (`compileOptions` source/target 17 ; `jvmTarget` suit par défaut). Les tests unitaires tournent sur la JVM 21.

## Conséquences

- Si le wrapper doit être lancé une première fois sous JDK 27 (avant que les critères existent), on utilise `JAVA_HOME=/usr/lib/jvm/java-21-openjdk ./gradlew …`. La marche à suivre est dans `README` (lot 1).
- Le lot 1 valide le comportement de `java { toolchain }` avec le Kotlin intégré. Si ce bloc pose problème, on le retire : les critères du démon suffisent.
- Passer à Gradle ≥ 9.8 ou au JDK 27 demandera un nouvel ADR, une fois que KGP l'aura validé.
